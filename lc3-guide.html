LC-3 Guide & Lessons

Follow 40 handbook-aligned lessons from computer architecture to complete programs. Each lesson includes a concept, a worked example and a quick check.

Reference: supplied LC-3 Instructions Handbook. Topics follow its architecture, syntax, operate, data movement, control-instruction and exercise sections. The notes below are concise teaching summaries, not a replacement for the full handbook.
Lesson 01 · Beginner

Introduction to LC-3

LC-3 is a 16-bit educational computer architecture. It exposes how a processor uses registers, memory and instructions.

Open lesson notes and example

The LC-3 has eight general-purpose registers (R0–R7), a 16-bit address space and a small instruction set. A program is assembled into machine words, loaded into memory and executed by the processor.

.ORIG x3000
AND R0, R0, #0
ADD R0, R0, #1
HALT
.END

Quick check: Name the three kinds of state you can inspect in the simulator: registers, memory and condition codes.

Lesson 02 · Beginner

The machine and its registers

Registers are fast storage locations inside the processor.

Open lesson notes and example

R0–R7 are 16-bit general-purpose registers. The PC holds the next instruction address. The condition codes NZP describe the latest result: Negative, Zero or Positive.

.ORIG x3000
ADD R2, R0, R1
HALT
.END

Quick check: If ADD R2, R0, R1 adds 7 and 4, which register receives 11?

Lesson 03 · Beginner

Memory organisation

LC-3 has 65,536 addressable locations, each holding one 16-bit word.

Open lesson notes and example

Addresses are 16-bit values. A program commonly starts at x3000. Instructions and data both occupy memory. The memory viewer helps you inspect assembled words and stored values.

.ORIG x3000
LD R0, VALUE
HALT
VALUE .FILL #42
.END

Quick check: How many bits are stored in one LC-3 memory location?

Lesson 04 · Beginner

Program structure and directives

Assembler directives organise a program; they are not ordinary processor instructions.

Open lesson notes and example

A typical source file uses .ORIG to set its starting address, .END to mark the end, .FILL to place one value in memory, .BLKW to reserve words and .STRINGZ to store a null-terminated string.

.ORIG x3000
VALUE .FILL x1234
SPACE .BLKW 8
TEXT .STRINGZ "LC-3"
.END

Lesson 05 · Beginner

ADD, AND and NOT

Operate instructions perform arithmetic and bitwise logic.

Open lesson notes and example

ADD DR, SR1, SR2 or ADD DR, SR1, imm5 adds values. AND uses the same operand forms for bitwise AND. NOT DR, SR1 inverts all 16 bits. ADD and AND immediate values are limited to -16 through 15.

.ORIG x3000
ADD R1, R2, #5
AND R3, R3, #0
NOT R4, R1
HALT
.END

Quick check: Write the instruction that adds 5 to R2 and stores the result in R1.

Lesson 06 · Intermediate

Condition codes

Many instructions update NZP based on the value they produce.

Open lesson notes and example

N is set for a negative signed result, Z for zero and P for a positive result. Branch instructions inspect these flags. A later instruction that updates flags can change which branch is taken.

.ORIG x3000
AND R0, R0, #0
ADD R0, R0, #0 ; sets Z
BRz ISZERO
HALT
ISZERO ADD R1, R1, #1
HALT
.END

Quick check: What condition code is set after an instruction produces zero?

Lesson 07 · Intermediate

Loading data: LD and LEA

Load instructions move values or addresses into registers.

Open lesson notes and example

LD R1, VALUE loads the word stored at VALUE. LEA R1, VALUE loads the address of VALUE. LD is useful for constants; LEA is useful for locating arrays and strings.

.ORIG x3000
LD R1, VALUE
LEA R2, VALUE
HALT
VALUE .FILL #12
.END

Quick check: Which instruction loads the address of LABEL into R3?

Lesson 08 · Intermediate

Base+offset and indirect loads

LDR and LDI provide additional ways to access memory.

Open lesson notes and example

LDR DR, BaseR, offset6 reads from the address formed by a base register plus a signed offset. LDI reads indirectly: it fetches a pointer from a PC-relative location, then reads the value at that pointer.

.ORIG x3000
LEA R2, ARRAY
LDR R0, R2, #1
HALT
ARRAY .FILL #4
      .FILL #9
.END

Quick check: If R2 contains x4000, what address does LDR R0, R2, #3 read?

Lesson 09 · Intermediate

Storing data

ST, STR and STI write register values into memory.

Open lesson notes and example

ST stores to a PC-relative label. STR stores using a base register plus offset6. STI stores indirectly through a pointer. These are useful for variables, arrays and results.

.ORIG x3000
AND R0, R0, #0
ADD R0, R0, #7
ST R0, RESULT
HALT
RESULT .BLKW 1
.END

Quick check: Which instruction stores R4 at the address R2 + 1?

Lesson 10 · Intermediate

Branching and decisions

BR changes the PC when the selected condition code is set.

Open lesson notes and example

BRn branches on negative, BRz on zero, BRp on positive. Combinations such as BRzp branch on either zero or positive. Use a comparison that sets NZP immediately before the branch.

.ORIG x3000
ADD R0, R0, #-1
BRzp AGAIN
HALT
AGAIN ADD R1, R1, #1
HALT
.END

Quick check: Which branch handles both zero and positive results?

Lesson 11 · Intermediate

Loops and counters

A loop repeats a block until a condition changes.

Open lesson notes and example

A common pattern initialises a counter, performs work, decrements the counter and branches while positive. Make sure the decrement updates condition codes before BRp. Avoid branches that can never reach a HALT.

.ORIG x3000
JSR DOUBLE
HALT
DOUBLE ADD R0, R0, R0
RET
.END

Quick check: What instruction commonly decrements a counter in R1 by one?

Lesson 12 · Advanced

Jumps and subroutines

Subroutines let you reuse a block of code.

Open lesson notes and example

JSR saves the return address in R7 and branches to a label. RET returns through R7. JSRR uses a base register. If a subroutine itself calls another subroutine, preserve the caller return address when needed.

.ORIG x3000
LEA R0, MESSAGE
PUTS
HALT
MESSAGE .STRINGZ "Hello LC-3!"
.END

Lesson 13 · Advanced

TRAP routines and I/O

TRAP calls operating-system routines for basic input and output.

Open lesson notes and example

Common routines: GETC (x20), OUT (x21), PUTS (x22), IN (x23), PUTSP (x24) and HALT (x25). PUTS expects R0 to point to a null-terminated string. OUT prints the character in the low byte of R0.

.ORIG x3000
LEA R1, WORDS
LDR R0, R1, #0
LDR R2, R1, #1
HALT
WORDS .FILL #10
      .FILL #20
.END

Quick check: Which trap outputs a null-terminated string whose address is in R0?

Lesson 14 · Advanced

Strings and arrays

Strings and arrays are stored as consecutive words in memory.

Open lesson notes and example

.STRINGZ stores one character per word followed by zero. Arrays can be accessed with a base address in a register and LDR/STR offsets. For longer arrays, use a pointer and a loop counter.

.ORIG x3000
LEA R0, MESSAGE
PUTS
HALT
MESSAGE .STRINGZ "Debug one step at a time"
.END

Lesson 15 · Advanced

Debugging and simulator workflow

Debugging means isolating the first point where actual behaviour differs from expected behaviour.

Open lesson notes and example

Assemble first, read the exact error and line, inspect labels and operand ranges, then reset and step one instruction at a time. Watch PC, registers, NZP, memory and console output. Use breakpoints where supported by the simulator.

.ORIG x3000
AND R0, R0, #0
ADD R0, R0, #5
ADD R1, R0, #-5
BRz EQUAL
HALT
EQUAL ADD R5, R0, #0
HALT
.END

Quick check: If a branch is not taken as expected, which state should you inspect first?

Lesson 16 · Advanced

Putting it together

Combine arithmetic, memory, decisions, loops and output into complete programs.

Open lesson notes and example

A robust program has a clear .ORIG, initialises registers it uses, uses labels consistently, respects immediate and offset ranges, and ends with HALT before data declarations where appropriate. Test normal, boundary and negative inputs.

.ORIG x3000
; initialise, compute, branch, store, halt
AND R0, R0, #0
ADD R0, R0, #6
ST R0, ANSWER
HALT
ANSWER .BLKW 1
.END

Lesson 17 · Intermediate

Binary, hexadecimal and signed values

LC-3 words are 16-bit patterns. Hexadecimal is a compact way to write those bits; signed two’s-complement interprets the top bit as the sign.

Open lesson notes and example

Use xFFFF for -1 in 16-bit two’s-complement.

ADD R0, R0, #1

Quick check: What decimal value does xFFFF represent as a signed 16-bit number? Answer: -1

Lesson 18 · Intermediate

Two’s-complement arithmetic

Negate a value by inverting all bits and adding one. This is the representation used for signed subtraction.

Open lesson notes and example

R1 now contains the two’s-complement negation of R0.

NOT R1, R0
ADD R1, R1, #1

Quick check: Which extra operation follows NOT when negating? Answer: ADD one

Open lesson notes and example

The first uses register mode; the second uses immediate mode.

Different instruction formats have different signed offset widths. LDR uses offset6; PC-relative operations commonly use offset9.

Open lesson notes and example

Keep the offset inside the signed 6-bit range.

Lesson 22 · Intermediate

LDI and STI indirect access

Indirect instructions use a memory word as a pointer. They are useful when the target address is not close enough for direct PC-relative access.

Open lesson notes and example

LDI reads the pointer at PTR, then reads the value at that pointer.

LDI R0, PTR

Lesson 23 · Intermediate

Condition-code discipline

Most operate and load instructions update NZP. A branch checks the most recently set flags, so avoid accidentally overwriting them before branching.

Open lesson notes and example

The ADD copy sets condition codes based on R1.

ADD R0, R1, #0
BRz ZERO

Quick check: Which flags are tested by BRzp? Answer: Zero or positive

Lesson 24 · Intermediate

Unconditional branching

BRnzp always branches because at least one of N, Z or P must be set after a valid result. It is often used for jumps over code.

Open lesson notes and example

This jumps to FINISH regardless of the current condition code.

BRnzp FINISH

Quick check: Which branch mask makes an unconditional branch? Answer: BRnzp
